## 1. Design Intent（设计意图）

- 产品属性：高频决策型交易页面（国内机票），强调“快决策、低疑虑、强转化”。
- 视觉气质：信息密度中高，层级清晰，价格与关键权益高对比突出，非关键信息弱化。
- 交互原则：先让用户完成“看得懂 + 能下单”，再提供细节扩展，不在首屏堆砌复杂解释。

AI 必须遵守：
- 优先保证信息层级，再追求装饰性。
- 价格、航班关键字段、CTA 为一级视觉重心。
- 非关键说明（规则、补充信息）默认二级或三级层级。
- 对话内容统一采用 **Feed 流连续呈现**，禁止默认卡片化拆分信息。

### 1.1 对话呈现策略（新增）

目标：所有 AI 对话以“时间顺序 Feed 流”承载，优先保证连续阅读与快速决策，不依赖卡片拼贴。

强约束：
- 主体内容必须渲染为 Markdown（标题、列表、强调、引用、代码块）。
- 单轮回复默认是一个连续消息块，不按“卡片组件”切割为多个视觉盒子。
- 若信息较长，使用 Markdown 层级（`##`、`-`、`1.`）解决可读性，不使用卡片堆叠。
- 可交互能力（如 CTA、操作建议）以内联按钮区或尾部操作条承载，不插入中段卡片。
- 仅在“强结构化数据”场景允许轻量块状容器（如价格日历、政策对比表），且必须可回退为纯 Markdown 文本。

禁用模式：
- 对话正文中大面积使用营销卡片、信息卡片、宫格式卡片。
- 为了视觉装饰把同一段逻辑拆为多卡片导致阅读跳跃。
- 使用卡片替代层级化文本表达（本可用标题+列表完成）。

## 3. Layout & Grid（布局与栅格）

移动端 H5 基线：
- 设计宽度：`375`（主稿）
- 安全边距：左右 `16`
- 常规内容区：`343` 宽（375 - 16*2）
- Feed 内容块内边距：`12` 或 `16`
- 列间距：`8` 或 `12`

布局策略：
- 页面结构：`顶部导航 -> 核心决策区 -> 辅助信息区 -> 底部行动区`
- 核心决策区必须包含：航班关键字段、价格、主 CTA。
- 扩展说明折叠显示，点击后展开，不抢首屏注意力。
- 对话区采用单列纵向 Feed，消息按时间顺序追加，不进行瀑布流卡片拼接。
- 消息主体优先 Markdown 排版，视觉盒子只作为系统级容器（如输入框、底部操作条）。

## 4. Component Spec（关键组件规范）

以下是 AI 必须优先复用的业务组件族。

> 补充：组件用于承载“交易信息与操作控件”，不应改变“对话内容以 Feed + Markdown 为主”的呈现主轴。

## 4.1 按钮（大/中/小、主/次）

结构：
- 元素：容器 + 文本 +（可选）图标
- 高度：
  - 大按钮：44~48
  - 中按钮：36~40
  - 小按钮：28~32

状态：
- `default`：可点击，主按钮使用品牌色。
- `pressed`：亮度降低或叠加黑色透明层。
- `disabled`：降低对比度，不可点击。
- `loading`：保留宽高，不抖动。

规则：
- 主 CTA 在一个视窗内最多 1 个。
- 次按钮不可与主按钮视觉权重相同。

## 4.2 价格组件（横向/纵向/暗黑）

结构：
- 价格主值（高优先级）
- 币种/单位（中优先级）
- 辅助说明（低优先级，可选）

状态：
- `normal`：展示基础价格。
- `discount`：同时展示原价与现价，原价需弱化并可删除线。
- `unavailable`：价格不可订，显示异常文案并降权。

规则：
- 价格色仅用于金额与优惠标签。
- 同模块最多一个最强价格视觉锚点。

## 4.3 标签与权益标（小/中/大、暗黑）

结构：
- 背景 + 文本（可选图标）

状态：
- `default`
- `emphasis`
- `disabled`

规则：
- 标签表达“属性”，不承载长文本说明。
- 同行标签数量建议不超过 3 个。

## 4.4 表单与输入

结构：
- 标题/占位提示/输入内容/反馈文案

状态：
- `default`
- `focus`
- `error`
- `disabled`
- `filled`

规则：
- 错误态使用 `color.warning`，并给出可执行修正文案。
- 输入区最小点击高度 40。

## 4.5 行程与航班信息卡片

结构：
- 出发/到达城市与时间
- 航司与航班号
- 中转/直飞信息
- 价格与 CTA

规则：
- 时间与价格是一级信息。
- 航司、机型、附加说明是二级信息。
- 超长字段优先截断并提供完整查看路径。

## 4.6 商务舱 Upsell 卡片（对话流内）

> 来源：CEO Review + Design Review + Eng Review 决策（2026-04-02）

### 视觉区分
- 使用 `.flight-card--business` 变体，与经济舱卡片明确区分。
- **金色左边线**：`border-left: 4px solid #c9a74e`
- **暖色渐变背景**：`linear-gradient(135deg, #fff 0%, rgba(201,167,78,0.04) 100%)`
- **金色边框**：`border-color: rgba(201,167,78,0.25)`

### 信息层级（5 级，优先级从高到低）
1. **价差标语**（一级）：顶部金色横幅，公式为"多花 ¥X，换来全平躺"，使用 `.upsell-tagline`
2. **航班信息**（二级）：出发/到达时间、航线、航司，复用经济舱卡片结构
3. **卖点 × 2**（三级）：座椅参数（180°全平躺｜198cm腿部空间）+ 舱内布局（1-2-1）
4. **评分**（四级）：旅客评分 + 好评率 + 准点率
5. **Accordion 触发**（五级）：展开/收起机型详情，动画使用 `cubic-bezier(0.16, 1, 0.3, 1)`

### 交互状态规范
| 状态 | 视觉表现 | 触发条件 |
|------|---------|---------|
| **骨架屏** | 金色边框 + shimmer 动画占位块 | CabinKB 数据加载中 |
| **正常** | 完整信息 + 金色左边线 + 价差标语 | 数据完整返回 |
| **部分数据** | 隐藏缺失字段，保留核心航班信息 | CabinKB 部分字段缺失 |
| **无库存** | 灰色调 + "暂无库存" 标签，CTA 禁用 | 商务舱无可售库存 |
| **错误** | 隐藏整个第三槽，不展示错误卡片 | API 异常或 B 分 < 阈值 |

### 订票按钮变体
- 商务舱订票按钮使用金色调：`color: #c9a74e; background: rgba(201,167,78,0.08)`
- 与经济舱蓝色 CTA 形成视觉区分

### CTA 跳转按钮
- 跳转到 H5 沉浸式详情页（全屏跳转，非弹窗）
- 箭头颜色使用 `var(--brand)` 而非硬编码色值

## 4.7 商务舱 H5 详情页锚定组件

### 顶部航班锚定栏
- 当用户滚动过 Hero 区域后，顶部固定显示航线/日期/价格信息
- 背景：`rgba(18, 18, 22, 0.88)` + `backdrop-filter: blur(12px)`
- 底部金色分割线：`border-bottom: 1px solid rgba(201, 167, 78, 0.2)`
- 动画：从顶部滑入，使用 `var(--ease)` 缓动

### 底部固定预订按钮
- Hero 可见时隐藏，滚动过 Hero 后显示
- 底部 Footer CTA 可见时隐藏（避免重复）
- 包含航班号 + 价格信息（金色高亮）
- 毛玻璃效果：`backdrop-filter: blur(9px)`

当 AI 在 Figma 生成或改图，**默认通过 Figma 官方 MCP**（读：`get_design_context` / `get_metadata` / `get_screenshot`；写：**`use_figma`**）。执行前须阅读技能 **figma-use**（每次 `use_figma` 前强制）。详细链路与本机端点见：`Qwen/.cursor/skills/figma-link-workflow/SKILL.md`。

必须按以下顺序：

1. 会话与读稿
- 确认 Cursor 已连接 Figma MCP（本机常见 `http://127.0.0.1:3845/mcp` 或 `https://mcp.figma.com/mcp`，以实际配置为准）。
- 用户若提供链接：解析 `fileKey`、`nodeId` 后先 `get_design_context`（必要时补 `get_metadata` / `get_screenshot`）。
- **不**将 Vibma（3056/3055、插件 Relay）作为本流程的默认前置检查。

2. 读取任务与页面结构
- 先输出页面信息架构（区块列表）
- 再落组件，不允许直接无结构铺画布

3. 组件优先复用
- 优先复用既有组件（按钮/价格/标签/表单/行程）
- 禁止在可复用场景下新建“同义组件”

4. Token 强约束
- 颜色、字号、间距、圆角必须来自本文 Token Contract
- 新增 token 时必须标注“新增原因 + 替代失败原因”

5. 状态齐全
- 交互组件至少给出 `default + pressed + disabled`
- 输入类至少给出 `default + focus + error`

6. 输出验收
- 输出节点清单（关键 Frame/Component 名）
- 输出未满足项（若有）与原因

**写入画布**：优先 **`use_figma`**；仅在官方 MCP 无法覆盖且用户明确要求时，才考虑 Vibma 或历史 HTTP 更新通道（不作为本项目标准）。

## 6. H5 Generation Protocol（AI 生成 H5 协议）

技术输出要求：
- 语义结构优先：`header/main/section/footer`。
- 样式优先使用 CSS 变量映射本文 token。
- 交互可用：按钮点击反馈、禁用态、表单错误态。
- 响应式：以 375 为主，兼容 320~430 宽度。
- 对话渲染层必须支持 Markdown（至少支持标题、列表、加粗、引用、代码块）。
- 对话主容器必须为单列 Feed 流，不得默认使用卡片网格布局。

代码约束：
- 不写死魔法数颜色；统一走变量。
- 不出现不可解释的绝对定位堆叠。
- 不牺牲可读性追求“像素级复制”。
- 不将每个段落包装为独立卡片组件；需要分层时优先使用 Markdown 结构。

可访问性最低要求：
- 关键控件可键盘聚焦（若为 Web 交互场景）。
- 文本与背景保持清晰对比。
- 图片/图标有替代说明（按场景适配）。

```text
4) 风险与回滚建议
5) 自检结论
```

## 9. QA Checklist（喂 AI 前必检）

- 文档内是否仍有“手动补充/待填写/占位符”字样：必须无。
- 是否给出 token、布局、组件状态、协议与模板：必须全覆盖。
- 是否明确了 Figma 与 H5 双端执行路径：必须明确。
- 是否包含连接检查与故障恢复命令：必须包含。
- 是否能直接复制 Prompt 开始执行：必须可以。

## 10. Do / Don’t（给 AI 的强约束）

Do：
- 先结构后样式。
- 先复用后新建。
- 价格、时间、CTA 做一级视觉锚点。
- 交互组件必须补齐状态。

Don’t：
- 不要随意新增颜色和间距值。
- 不要把标签当段落文字容器。
- 不要在首屏堆叠低价值说明。
- 不要输出“看起来像设计稿但不可实现”的代码。
