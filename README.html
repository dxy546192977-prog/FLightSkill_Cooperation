项目动因
为什么想做这个 Skill？
01
重复性工作 · 数据覆盖低
数据分散、字段不全，餐食、座椅布局等关键信息无法完整展示；每次上新都需要人工整理，效率极低。
02
人工成本高 · 开发周期长
过去视觉表达依赖 3D 建模，单次建模成本约 10 万元，整个项目周期极长，难以规模化复制。
💡
核心机会：用 AI Agent 替代人工，实现数据自动采集 → 智能推荐 → 视觉自动生成的全链路自动化，大幅降低成本并提升覆盖广度。

子 Skill 02 · Business Class Recommendations
推荐规则 判断引擎
📐 倾向分 B · 排序公式
B = clamp(B, −40, 80)
R = R₀ + w × B
R₀ = 业务基础分（价格/时长/直飞/库存）
w ∈ [0.3, 0.6]，与 R₀ 量级同比缩放

📐 排序公式
B = clamp(B, −40, 80)
R = R₀ + w × B
R₀ = 业务基础分（价格/时长/直飞/库存）
w ∈ [0.3, 0.6]，与 R₀ 量级同比缩放
⚠️ 计分注意事项
①同类多词命中，不重复加分，每类最多 +1 次
②「出差」+「报销」同属商务场景，合计仅 +15，不是 +30
③减分整轮计一次，多轮对话不重复惩罚
④可选叠加上一轮一句，增强上下文感知
⑤B 值截断在 [−40, 80]，防止极端值影响排序
推荐规则详解 · 第三槽
第三槽 曝光策略
B ≥ 20
高意向
优先展示商务舱
可放宽价差阈值，主动推荐第三槽；排序分 R 显著提升
🏁
−20 < B < 20
中性
走默认价差策略
按正常价差规则决定是否展示，不主动放宽也不降级
🔵
B ≤ −20
价格敏感
隐藏或强降级
第三槽不展示或降至最低权重，避免强推引发反感
🔴
💡 计算示例
「红眼航班，带老人出行」
红眼 +20 + 老人 +25 = B = 45
→ 第三槽优先展示，价差阈值放宽
「出差，帮我找最便宜的」
出差 +15 + 最便宜 −35 = B = −20
→ 恰好触发阈值，第三槽隐藏或强降级
「帮我订去北京的票」
无关键词 = B = 0
→ 走默认价差策略，正常判断
📌 前提条件
以上策略均在商务舱有库存时生效。
无库存时，无论 B 值多高，第三槽均不展示。
价差阈值由产品策略配置，非硬编码。
